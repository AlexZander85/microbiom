# Микрокосмос — внутренняя вселенная

Русскоязычный образовательный исследователь микробиома человека, **10+**. Версия **0.12 / Pulse Relay & Contact Investigation**: настоящие объёмные меши, перспективная камера, depth buffer, аппаратный instancing и выбор лучом. Canvas2D используется только для подписей, **не вместо 3D-сцены**.

Без внешних runtime-библиотек, CDN, скачивания шрифтов/моделей и обязательной сборки.

## Запуск готового проекта

**Без сервера:** скачайте и откройте [`standalone.html`](standalone.html) двойным щелчком в современном браузере с WebGL2. Внутри код и стили, около 591 КБ. Node/npm/Python для запуска этого файла не нужны. Проверен `file://` с заблокированными HTTP-запросами.

**Модульные исходники:** разместите каталог на любом статическом хостинге или:

```sh
python3 -m http.server 8000 --bind 0.0.0.0
```

Откройте `http://localhost:8000`. В Arena — живой предпросмотр порта **8000**. `index.html` использует ES modules и требует HTTP. Само приложение не вызывает localhost, API или внешние сервисы.

При отсутствии WebGL2 показывается объяснение и ссылка на [`classic.html`](classic.html), сохранённую старую Canvas-версию. Для неё нужен весь каталог через HTTP; отдельный новый standalone не содержит второй движок.

**Нет.** [Поэлементная матрица готовности](docs/IMPLEMENTATION_STATUS.md) отделяет рабочие функции от частичных и отсутствующих. В 0.5 локальные процессы уже вычисляются, но многомасштабная физиология, полный иммунитет, расширенная генетика/химия, научная калибровка и аппаратная приёмка 60 FPS ещё не завершены.

В микромире нажмите «Выбирать слои»; для анатомии выберите жителя → «Устройство» или откройте его из атласа. Кнопки частей находятся под сценой. Пробел собирает и разбирает схему, в том числе на паузе.

## Новое в 0.12: выбранная порция → кислород и расследование контакта

**Толстая кишка → «От выбранной еды до кислорода».** Два пищевых импульса имеют отдельные метки происхождения углерода. Выберите порцию и проследите её доли в ацетате, бутирате, ткани, биомассе и выходах. Тканевое окисление расходует фактический запас O₂; отдельно считаются приток, обмен с просветом и вынос. Три варианта: прервать использование ацетата, прервать окисление в ткани, ничего не прерывать. Есть восстановление и общий кислородный ответ A/B.

**Метка массы — не весь причинный эффект порции.** Общий сдвиг O₂ не раскладывается на независимые «эффекты еды»; связанный с меткой расход показывается отдельно. Выбор метки меняет только просмотр, сохраняется в JSON и работает при перемотке. Старый суммарный режим остаётся отдельно, без вымышленной точности.

**«Что изменится, если прервать контакт?»** Подготовленная пара донора/получателя, пять вариантов: ранний разрыв с возвратом, ранний без возврата, поздний разрыв, перемещение пары вместе, отсутствие вмешательства. Используется настоящее правило конъюгации движка: ранний разрыв отменяет попытку, возврат начинает её заново, поздний не удаляет уже полученную копию. Есть остановки для наблюдения, A/B, реальные события, графики и итог.

[Модели, параметры и ограничения](docs/20-pulse-relay-and-contact.md) · [Браузерный протокол](docs/benchmarks/pulse-contact-validation.json). **163/163 unit-теста и 8 браузерных маршрутов** пройдены, включая offline, сохранение метки, rewind/fork и прежний free-flight. Это техническая проверка, не научная калибровка или клинический прогноз.

## Добавлено в 0.11: нутриентный путь кишечник → мозг и free-flight

**Толстая кишка → «Кишечник сообщает — мозг получает сигнал»**. Вычисляются добавленная глюкоза (ммоль/мМ), её перенос и отдельный нервный путь: сенсор кишечного эпителия → глутаматная передача → вагальный афферент → стволовая мишень NTS. Четыре контроля различают всасывание, синаптическую передачу и доставку нервного сигнала; после восстановления связи второй импульс снова вызывает ответ. Есть A/B, графики, баланс, журнал, сохранение и перемотка.

**Это первый нутриентный путь, не полная ось и не вычисление влияния микробиома на настроение.** Механистическая основа — преимущественно мышиные исследования; численные параметры и нормированный ответ NTS учебные. Нет ГЭБ, микробного источника, гормонально-иммунной интеграции или обратного эфферентного контура. [Научные основания, единицы и границы](docs/18-gut-brain-neural-path.md).

**Свободный полёт:** кнопка ✥ или F в фокусе сцены. WASD, Q вниз / E вверх, Shift быстрее, перетаскивание/стрелки — взгляд; колесо — скорость; Esc — орбитальный режим. Есть экранные кнопки. Камера-сфера сталкивается с треугольниками твёрдых поверхностей, учитывает грани/рёбра/вершины, скользит и не туннелирует на большом шаге. Жидкие слои и микробы проходимы. Полёт происходит внутри выбранного пространства; смена масштаба остаётся отдельной навигацией. [Алгоритм и ограничения](docs/19-free-flight.md).

**149/149 unit-тестов**, новый и шесть прежних браузерных маршрутов. Проверены контакты с телом/тканью через обычные клавиши, четыре контроля нервного пути, replay, mobile 390px, восстановление WebGL и offline. [Протокол](docs/benchmarks/axis-flight-validation.json). Нативный WebGL2 сохранён; новых runtime-зависимостей нет. Старые движки 0.5–0.10 не изменены.

## Добавлено в 0.10: защита без войны и первый этап связанной физиологии

**Толстая кишка → мини-исследования → «Защита без войны»**. Одинаковый новичок попадает в A/B. Потеря потребителей общего ресурса освобождает нишу; возвращение нужной функции ограничивает его без атак. Четыре варианта: вернуть R-потребителей, вернуть равную биомассу Q-потребителей, не восстанавливать, не нарушать. Фигурки — функциональные группы, не отдельные клетки.

**«Одна еда — разные пути и задержки»** использует тот же движок: желудочный → тонкокишечный → колонический резерв; всасывание → портальный → печёночный отсек → кровь → использование/выведение. Карта показывает одно общее состояние, а не запускает отдельную модель для каждого узла. Есть A/B, материальный баланс, реестр переносов, сохранение и перемотка.

**Это этап 1; именно в опытах 0.10 ось кишечник–мозг не вычисляется.** В 0.11 для неё появился отдельный нутриентный нервный путь. Условные D/R/Q/M не являются глюкозой, бутиратом или серотонином. Нет мозговой мишени, ГЭБ, настроения и диагноза; прежние девять обзорных биотопов остаются независимыми примерами. [Поэтапная архитектура](docs/16-connected-physiology-plan.md) · [Реализованные правила и границы](docs/17-competition-and-transport.md).

**133/133 unit-теста**, новый браузерный маршрут и пять прежних пройдены. Оба новых опыта проверены в автономном HTML без сети. [Протокол](docs/benchmarks/connected-validation.json). Старые записи используют прежние движки 0.5/0.7/0.8/0.9. Это техническая проверка, не клиническая и не аппаратная GPU-приёмка.

## Добавлено в 0.9: слюна–pH–эмаль и уход за зубами

**Полость рта → лаборатория → «Что остаётся после чистки?»**. Выберите прогноз и один из шести вариантов: без ухода, одна чистка, повторная чистка, вода, фторсодержащий или антисептический ополаскиватель. Одинаковые сахарные нагрузки и независимый контроль позволяют отделить снятие налёта, кислотность и минеральный баланс.

В 3D видны прикреплённые микроколонии, объём налёта, кислотные ореолы, поток слюны и изменение поверхности эмали. Есть этапы накопления/ухода/длительного наблюдения, графики, объяснения, заметки, replay и свободные ветки. Слюноотделение и сахарные нагрузки можно менять отдельно.

**Не медицинский таймер и не рейтинг средств.** Чистка не чинит эмаль мгновенно, полоскание не заменяет механическую гигиену, ранняя потеря минералов отделена от необратимого структурного дефекта. Чистка в опыте механическая, чтобы фтор был отдельной причиной, — это не совет отказаться от фторсодержащей пасты.

[Правила и ограничения](docs/15-saliva-ph-enamel.md) · [Протокол шести вариантов](docs/benchmarks/oral-validation.json). **123/123 unit-теста**; проверены браузерный маршрут, мобильная панель и offline. Старые сценарии сохраняют движки 0.5/0.7/0.8.

## Сохранённый модуль 0.8: оборот слизи

В толстой кишке → лаборатория под сценой → **«Кто обновляет защитное покрытие?»**. Прогноз → дефицит доступного микробам субстрата → возврат притока → наблюдение восстановления. Три кнопки останавливают опыт на этапах; рядом независимый контроль A.

Хозяин расходует собственный пополняемый резерв на секрецию; материал переходит из внутреннего слоя в наружный, потребляется микробами и выводится из участка. Два объёмных WebGL2-слоя меняют высоту по вычисленным запасам. Есть локальный перенос веществ, углеродный баланс, графики, мысли о текущем питании, причинные события, итог/заметка и точный replay с ветвлением.

**Потребление муцина само по себе не равно вреду; слизь не равна целостности эпителия.** Нет связи «пропустил обед → заболел». Пороги, скорости и масштабы учебные. В свободном режиме производство хозяина можно менять отдельно от притока субстрата. В версии 0.8 добавлялся только оборот слизи; оральный модуль появился отдельно в 0.9.

[Правила, параметры и ограничения](docs/14-mucus-turnover.md) · [Протокол проверки](docs/benchmarks/mucus-validation.json). **108/108 unit-тестов**; отдельная браузерная проверка 3D, A/B, replay, мобильной панели и offline.

## Сохранённый модуль 0.7: персистенция — пережить не значит стать устойчивым

В толстой кишке → лаборатория под сценой → карточка **«Пережить — не значит стать устойчивым»**. Прогноз → первое равномерное воздействие → удаление препарата и восстановление роста → повторная проверка. Есть кнопки остановки после каждого этапа.

Чувствительные S, временно медленные S и наследуемые R-demo сравниваются отдельно. Потомки исходных персистеров сохраняют метку происхождения, но не наследуют автоматически медленное состояние. Таблица этапов, A/B-графики, рассказчик, генеалогия и replay показывают вычисленные результаты, не заранее назначенные победы.

Это один учебный механизм персистенции, **не универсальная «спячка», не споры и не схема лечения**. Препарат подаётся равномерно, чтобы не спутать состояние клетки с недополученной экспозицией. Старые шесть сценариев и их записи сохранены на прежних правилах. [Модель, параметры и ограничения](docs/13-persistence.md).

## Основа 0.6: понять, почему это произошло

В **толстой кишке → лаборатории под сценой** выберите одну из трёх карточек:

- **Копия, а не потеря:** передача pDemoR и наследование дочерними клетками.
- **Один вид — разные судьбы:** индукция профага и сравнение с контролем.
- **По разные стороны границы:** доступ к ткани не равен немедленному поглощению.

Запишите прогноз → наблюдайте или нажмите **«Рассчитать до итога»** → сравните A/B → откройте **«Мой итог»** и напишите своё объяснение. Прогноз и заметка сохраняются в JSON. Клик по событию открывает причинного рассказчика; ссылки и перемотка возвращают к предшествующим стадиям.

Временные A/B-графики показывают восемь показателей локального опыта. **Метаболическая эстафета** связывает пять реальных потоков с полями сцены: субстрат → ацетат → сосед → бутират → ткань. Это суммарный учёт, не придуманный путь отдельной молекулы. Счётчики не меняют биологию; старые записи 0.5 совместимы. [Управление, границы и проверки](docs/12-discovery-learning.md).

## Основа 0.5: вычисляемая лаборатория процессов

В толстой кишке под сценой выберите сценарий в **«Лаборатории живых процессов» → «Начать опыт»**. Доступны:

- контактная конъюгация с сохранением плазмиды у донора, наследованием и изменением чувствительности; T6SS с совместимостью/иммунностью;
- цикл фага до лизиса и потомства, лизогения, наследование профага и индукция;
- тканевый сигнал → хемотаксис фагоцита → поглощение → переваривание;
- рост/деление, почкование, споры/прорастание и упрощённые гифальные ветви;
- 3D-диффузия и локальные реакции, углеродный реестр;
- генеалогия, причинный журнал, независимый контроль, сохранение/загрузка JSON, перемотка и продолжение от выбранного шага.

Это **не декоративные анимации**: процессы меняют состояния агентов и химических полей. Но это ограниченный учебный участок, а не вся физиология человека. Общая агрегированная модель в это время остановлена — события не считаются дважды. [Как пользоваться, что считается и какие есть ограничения](docs/10-local-processes.md).

## Что изменилось принципиально

- Центральная вращаемая **3D-фигура человека** с полупрозрачной оболочкой и объёмными органами.
- Обратимый маршрут **человек → орган → ткань → микромир**, управляемый камерой, колесом, шкалой и кнопками. Межмасштабный переход явно семантический, не обещание единой физической линейки от метров до нанометров.
- **9 биотопов**; различающиеся поверхности/рельеф/структуры. По умолчанию **3600** пространственных представителей, профили 1800/7000. Для низкой биомассы — до 240. Это не реальное число микробов тела.
- Выбор конкретного экземпляра, слежение камерой, карточка, живые модельные показатели и отдельный клеточный инспектор.
- Пять вмешательств с ограничениями по месту; предсказание, **внесение пищи кликом**, независимый контроль без вмешательства, журнал, JSON-экспорт.
- Атлас из 16 представителей пяти групп, поиск, простой/научный текст и источники.
- Разбор слоёв; отдельные WebGL2-схемы T6SS, конъюгации и фага. Это иллюстрации механизмов, не скрытая имитация работающего генетического симулятора.
- Пауза, сброс, добровольный тур, reduced-motion, клавиатура, мобильная компоновка, восстановление графического контекста.

## Эксперимент: стоит ли переходить на Three.js

**[Сравнительная лаборатория](renderer-lab.html)** · **[автономный файл лаборатории](renderer-lab-standalone.html)** · **[результаты и решение](docs/08-renderer-decision.md)**.

Основное приложение **не мигрировано**. Ускорения в software-тесте не обнаружено; полезность для разработки подтверждена на конкретных функциях, аппаратная GPU-проверка остаётся открытой.

| Рассмотреть оболочки | «Устройство»; «Вернуться в сообщество» для выхода |
| Разобрать / собрать | Кнопка слоёв справа или пробел при фокусе сцены |
| Внести пищу | Клетчатка/сахар → предсказание → клик в микросреде |
| Отменить внесение | Escape при фокусе сцены |
| Мысли / темп анимации / графика | Панель над микромиром; темп анимации не меняет физиологическую модель |
| Пауза / скорость / контроль | Панель «Пульс микромира» под сценой |

## Модель и границы

Детерминированная **агрегированная учебная модель**, шаг 1/30 с; графические представители и число треугольников не определяют массу населения. Контроль имеет тот же seed, биотоп и модельное время. В обзоре локальная пища влияет на визуальную доступность/активность; в лаборатории действует отдельный агентный расчёт с пространственными полями и шагом 0,1 учебной единицы времени. Начальные доли условны, не универсальные измеренные частоты таксонов.

Это готовая запускаемая исследовательская версия, **не завершение всей долгосрочной научной программы**: нет калиброванной/адаптивной иммунологии, всех способов HGT, разнообразия фаговых и грибных циклов, полноразмерных геномов, медицински точной анатомии, полного набора видов или доказательного прогноза здоровья/настроения. Телеметрия не медицинская. Читайте §11 спецификации.

**Производительность:** 60 FPS остаётся целью на реальном GPU, не подтверждённым результатом. В headless Chromium с программным SwiftShader плотная новая 3D-сцена работает медленно. Замеры старой Canvas/WebGL1-версии к ней не относятся. Проверка на аппаратном GPU, Safari/Firefox и реальных телефонах ещё нужна.

## Архитектура

- `src/expedition.js` — интерфейс, ввод, фиксированный шаг, контрольный опыт, журнал.
- `src/local/` — пространственная химия, жизненные состояния, контакты, наследование, replay, интерфейс и графический адаптер локального участка.
- `src/model.js`, `src/data.js` — расчёт модели и образовательные данные.
- `src/webgl2/math.js` — перспективная камера и лучи.
- `geometry.js` — адаптация Hermite/профилей/кадров/труб anatomy к треугольным мешам.
- `gpu.js` — GLSL ES 3.00, VAO, буферы экземпляров, свет/туман/поле.
- `cloud.js` — массивы представителей и локальное визуальное питание.
- `world.js` — человек, органы, ткань, сцены и переходы.
- `classic.html`, `src/app.js`, `style.css` — историческая 2.5D-версия, не основной проект.

Исходные модули anatomy сохранены. Математика `iso-kit.mjs`/`lathe.mjs` и пружины/огибающие `gl.mjs` используются непосредственно. Трубная архитектура адаптирована к мешам: SVG-d/Path2D не подменяют WebGL2. Ортографическая `glCamera(P)` не используется вместо перспективной камеры.

## Проверки разработчика

Без установки зависимостей:

```sh
node --test tests/*.test.js
# или npm test
```

Опциональные браузерные проверки, не часть пользовательского запуска:

```sh
npm ci # необязательные инструменты разработчика; версии зафиксированы
node tests/browser-webgl2.mjs
node tests/structure-browser.mjs
node tests/local-browser.mjs
node tests/learning-browser.mjs
node tests/persistence-browser.mjs
node tests/mucus-browser.mjs
node tests/oral-browser.mjs
node tests/journey-webgl2.mjs
node tests/living-browser.mjs
node tests/performance.mjs
```

Нужен запущенный статический сервер. `TEST_URL` меняет его адрес, `BENCH_MS` — время замера каждой сцены. В минимальной Linux sandbox пакет Chromium может потребовать NSS/NSPR из своего `al2023.tar.br`; в текущей sandbox использовался `LD_LIBRARY_PATH=/tmp/lib`. Тесты не отключают web security. Headless-аудит **не нужен для запуска проекта**.

После изменения исходников сопровождающий обновляет готовый offline-файл:

```sh
python3 tools/make_standalone.py
```

Это детерминированный локальный упаковщик, не пользовательская Node-сборка. `standalone.html` намеренно хранится в репозитории. Не редактируйте его вручную.
