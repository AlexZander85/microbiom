# Three.js или собственный WebGL2: проверка на нашем проекте

**Дата:** 15.10.2026, местное время. **Статус:** сравнительный прототип готов; основное приложение не мигрировано. **Three.js:** локальная зафиксированная версия 0.186.1, MIT.

## Решение

**Не переписывать основной проект целиком сейчас.** Прототип подтвердил, что существующая геометрия совместима с Three.js, точный выбор/окклюзия внедряются без собственного треугольного raycaster, офлайн-доставка сохраняется. Он **не подтвердил ускорение** и не проверил производительность будущих стандартных материалов, теней, сложной анатомии и всей экспедиции.

Для дальнейшего развития сложной графики Three.js остаётся предпочтительным кандидатом: граф сцены, материалы, загрузка анатомических моделей и готовая геометрическая инфраструктура полезнее, чем расширение собственного движка ради этих функций. Это инженерная оценка стоимости сопровождения, **не измеренный выигрыш в сроках**.

Рекомендуемый следующий этап — перенос одного законченного тканевого сценария с динамическими экземплярами и реальными материалами, затем аппаратный GPU-тест. Только после этого менять основной вход. Модель биологии, данные, anatomy и исследовательский интерфейс не переписывать. Не держать два production-движка бессрочно.

## Что поставлено

- `renderer-lab.html?renderer=three` и `?renderer=native` — переключаемые рендереры одной замороженной сцены.
- `renderer-lab-standalone.html` — тот же эксперимент одним файлом, работает через `file://` без сети.
- `src/render-lab/fixture.js` — единый исходный набор геометрии и экземпляров, камера, хеш буферов.
- `three-adapter.js` — BufferGeometry / InstancedMesh / RawShaderMaterial, точный picking и правила окклюзии.
- `native-adapter.js` — тонкая оболочка над существующим `GPU`, не новый «упрощённый конкурент».
- Подсветка слоя через наведение/фокус: остальные группы приглушаются; показ/скрытие слизи; выбор конкретного экземпляра.
- 10-секундный замер и экспорт JSON для проверки на компьютере пользователя. При потере контекста, скрытии вкладки или изменении размера замер отменяется, а не публикует недостоверные результаты.

Основной `index.html` по-прежнему работает на собственном WebGL2. Прототип не добавляет в него иммунологию, PDE, free-flight, генеалогию или replay.

## Условия сравнения

Тестовый стенд намеренно проще полной экспедиции. **Это не прямое сравнение с прежними ~3.12 FPS главной страницы**: другой состав сцены, отсутствие per-instance culling, другая версия Chromium.

| Параметр | Оба рендерера |
|---|---|
| Биология | Один seed, одинаковый snapshot, модель заморожена |
| Представители | 3600, всего 3603 экземпляра с тканью/слизью |
| Геометрия | Общая `microbeGeometry()` и Hermite/frames anatomy, не похожие примитивы разной детализации |
| Треугольники | 635 672 |
| Draw calls | 9 |
| Камера | Одинаковые eye/target/FOV/near/far и VP-матрица |
| Canvas | 1010×540, DPR = 1; viewport браузера 1100×900 |
| Материалы | Одни vertex/fragment shaders, одинаковые blend/depth/side; без теней/PBR |
| Режим | Без MSAA, LOD, автоматического DPR и per-instance culling |
| Обновление данных | Instance-буферы загружаются каждый кадр в обоих вариантах |
| Порядок | Последовательно AB / BA / AB, один активный canvas |
| Прогрев | 10 кадров перед каждым замером |
| Длительность | 10 секунд на прогон, 3 прогона каждого варианта |

Three.js использует RawShaderMaterial для контролируемого сравнения. Это **не** тест производительности MeshStandardMaterial, теней или post-processing. Матрицы экземпляров дополнительно сохраняются на CPU для raycasting, тогда как шейдер получает исходные атрибуты собственного движка; эта избыточность допустима в прототипе, но не предлагается как окончательный формат.

## Результаты

Среда: Chromium **153.0.8010.0**, ANGLE/Vulkan **SwiftShader**, программный renderer Linux sandbox. Полные исходные результаты: [renderer-comparison.json](benchmarks/renderer-comparison.json).

| Порядок | Рендерер | Среднее FPS | p95 кадра |
|---|---|---:|---:|
| 1 | Native WebGL2 | 2.61 | 400.0 ms |
| 2 | Three.js | 2.34 | 483.4 ms |
| 3 | Three.js | 2.08 | 516.6 ms |
| 4 | Native WebGL2 | 2.13 | 483.4 ms |
| 5 | Native WebGL2 | 2.11 | 500.0 ms |
| 6 | Three.js | 2.05 | 516.7 ms |

Медиана средних FPS трёх прогонов: **2.13 native / 2.08 Three.js**, разница около 2.3% в пользу native. Заметен дрейф скорости по ходу теста; выборка мала (21–27 интервалов за прогон). Это не статистическое доказательство постоянной разницы 2.3% и тем более не прогноз для реального GPU. Ускорение от замены API не обнаружено.

В JSON отдельно указано время исполнения JS-вызова `render()`. Оно не является чистым временем GPU: команды асинхронны, возможны ожидания драйвера. `gl.finish()` для искусственной синхронизации не используется.

### Эквивалентность картинки

Сравниваются реальные RGBA-пиксели WebGL, без текста интерфейса:

- 2 181 600 каналов;
- 1008 различаются: **0.0462%**;
- средняя абсолютная ошибка **0.01585 / 255**;
- максимальная локальная разница **97 / 255**.

То есть картинки практически одинаковы, но **не побитово идентичны**. Небольшое количество пикселей с большой разницей не скрывается средним показателем. Порог регрессии — средняя абсолютная ошибка <0.5 / 255.

### Что действительно стало проще

В Three.js выбор получает instanceId из встроенного пересечения треугольников; наша обвязка сопоставляет его ID представителя и применяет правила:

1. Клетка перед тканью выбирается.
2. Непрозрачная ткань перед клеткой блокирует выбор клетки.
3. Прозрачная слизь пропускает или блокирует луч по явной настройке.
4. Скрытый слой не блокирует луч.
5. Режим выбора слоёв исключает микробов из целей.

Эти правила проверены на контролируемых сценах, а реальный клик — в браузере. Сферические границы используются Three.js только как ускоряющая предварительная проверка; окончательное попадание определяется треугольником. При сложных моделях может понадобиться BVH; его здесь нет.

## Проверки и исправления

- **29 unit-тестов PASS:** прежние 22 + 7 тестов совместимости буферов, picking/окклюзии/политики слизи и камеры.
- Парный browser-тест: одинаковые snapshot/буферы/камера/счётчики/пиксели, настоящий click, фокус слоёв, переключение слизи, неизменность модели.
- Оба backend в автономном файле, без HTTP-запросов.
- Мобильная компоновка 390 px, клавиатурная камера.
- Потеря WebGL отменяет измерение; отсутствие WebGL выдаёт объяснение. Восстановление самого прототипа предполагает перезагрузку, не заменяет восстановление основной сцены.
- Повторный полный `tests/browser-webgl2.mjs` основной экспедиции — PASS.
- Точное пересечение выявило почти незаметные отверстия на полюсах мешей: минимальный радиус .0001 не давал замкнуть поверхность. Концы профиля теперь допускают нулевой радиус; это исправление общего ядра проверено для обоих вариантов.
- Обнаружено различие формата default framebuffer: для Three.js явно передан контекст с теми же атрибутами, что у native. Сравнение RGBA проводится после исправления, не после исключения альфа-канала из метрик.

## Размер и зависимости

- Основной автономный проект: около **239 КБ**, Three.js в него не включён.
- Автономная сравнительная лаборатория с обоими backend: около **630 КБ**.
- Оригинальные локальные ESM-файлы Three.js: около **2.12 МБ** до минификации/HTTP-сжатия.

Это разные по функциональности документы, а не точный прогноз размера мигрированного приложения. Лицензия, версия, URL пакета и SHA256 сохранены в `vendor/three/README.md`. Npm/esbuild используются только сопровождающим для упаковки; пользователь открывает готовый HTML.

## Как повторить

Модульная версия — через статический сервер порта 8000. Runtime ничего не скачивает.

```sh
npm ci                         # только инструменты разработчика
npm test
npm run lab:bundle
node tests/renderer-lab.mjs
```

В минимальном Linux этой sandbox Chromium требует библиотеки из его `al2023.tar.br`; здесь использован `LD_LIBRARY_PATH=/tmp/al2023/lib`. `TEST_URL` меняет адрес сервера, `BENCH_MS` — длину каждого прогона, `SKIP_BENCH=1` запускает только функциональные проверки без перезаписи результата benchmark. `CHROME_EXECUTABLE` позволяет указать локальный Chromium; при этом тест не добавляет флаг `--disable-gpu`, но фактический renderer всё равно надо проверять в JSON.

Для реального пользовательского GPU проще открыть лабораторию в обычном браузере, не менять окно, выполнить по три замера каждого варианта в чередующемся порядке и экспортировать JSON. Никакой результат этого стенда не объявляется научной валидацией модели или достижением 60 FPS.
